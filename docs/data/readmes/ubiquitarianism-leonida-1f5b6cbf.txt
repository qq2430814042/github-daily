Leonida is a static recompilation project. The Xbox Series CPU is x86-64 like a PC, so the game's code is loaded
and run natively, and the console's system software is reimplemented. The console's precompiled RDNA2 GPU programs
are translated to SPIR-V for Vulkan. The game's models, textures and audio are read from your package. All of this
happens on your PC, from your own copy of the game.

This repository does not contain the game, keys or an executable, and it does not explain how to get them. You
need your own copy, with its files already readable on disk. Nothing here decrypts or works around any protection.
Everything the build creates (the generated shaders, extracted assets, the runtime folder and your saves) comes
from your game and stays on your PC. Never share those files.

This is a continuation of NotRexed's Leonida project. The original
author has left the project, and development continues here with its full commit history. Credit for the work up to
that point belongs to NotRexed and the contributors listed in the history.

Project status

Early. The game does not boot yet. Everything that can be done without the game's executable is in place, so
work on booting can start as soon as one is available to a developer.

Untested against the real executable |
| Xbox D3D12 → Vulkan | ⚠️ In progress. A Vulkan-backed device behind the Xbox-ABI proxy creates queues, command lists, fences, descriptor heaps, committed, placed and reserved resources, render-target and depth views (3D targets included), texture views and samplers (2D, cube, 1D and 3D views, the depth and stencil planes of depth-stencil textures, packed formats such as B5G6R5, B4G4R4A4 and R9G9B9E5, buffer SRVs — raw, structured and typed; they go into the bindless set), root signatures, pipelines and query heaps, and draws run on Vulkan. Barriers, clears, uploads, copies (BC included), colour resolves, predication, CPU-side texture reads and writes, and occlusion, timestamp and pipeline-statistics queries run on Vulkan, checked on one GPU. The console-shaped command-list proxy, the measured PresentX queue slots (30/32, layout-detected) wired to the presentation core, and AllocateUploadMemory (list slot 148, a mapped-upload arena whose addresses translate to buffer device addresses in root descriptors and IA/SO views) cover the console-ABI surface the package measures. Still open: the console list tail and the descriptor-table record model (plan) |
| Ray tracing (BVH) | ⚠️ In progress. BuildRaytracingAccelerationStructure builds BLASes and TLASes on the GPU in the console's XDXR BVH4 layout (the default; LEONIDA_RT_AS=khr uses Vulkan's own acceleration structures instead), which the translated shaders walk themselves through image_bvh_intersect_ray (all four triangle node types, TRI0-TRI3, with the barycentric remap byte); the GPU builder writes TRI0 and TRI1 leaves. Updates refit instead of rebuilding, and clone, compaction and the compacted/current postbuild sizes work; checked against a CPU reference on synthetic scenes. The build descriptions are recovered from the package's XboxBvhBuilder.dll (notes). The game's *_bvh4.rpf packs are measured: offline-built, dehydrated BLASes that rehydrate through that DLL with their geometry from the drawables in levels.rpf (measured on 8 of the 10 sampled BLAS; notes). Not done in the builder: serialization. TRI1 pairing (no memory saved yet) and BOX16 nodes for MINIMIZE_MEMORY BLASes (an assumed switch) are in (notes). Open: whether the game rehydrates the packs or rebuilds them (#313) |
