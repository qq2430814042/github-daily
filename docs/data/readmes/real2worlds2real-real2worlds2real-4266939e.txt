Citation and source history

From observations of a real scene to a policy prepared for the real robot. An agent (ASTRA) does the work through
layered skills and tools it selects as needed, inspects the evidence each step produces and revises its own results.
Simulation success is intermediate evidence; real validation is run and reported by people.

Start a reconstruction with the agent module workflow. One astra-e2e run can use calibrated cameras and poses, individual object workers, native physics checks and scene assembly. Choose an object, scene or policy handover as the goal.

Public interfaces

| Component | Python package | Command |
|---|---|---|
| Real2Sim Harness builds and reviews editable assets in task workspaces. | real2sim_harness | real2sim-harness |
| Calibrated Scene Reconstruction reconstructs metric scenes from capture, places the robot, and checks physics and delivery. | calibrated_scene_reconstruction | calibrated-scene-reconstruction |
| Policy station develops, freezes and evaluates a policy under a task budget. | astra_station | astra-station |
| End-to-end workflow binds the accepted scene to a station task and prepares the handover. | astra_e2e | astra-e2e |

Use the configuration templates to start a run. The reconstructed examples include interactive USDZ scenes for screw closure, gear meshing, insertion, cup nesting and pushing.

The two parts do not import each other. Part 1 hands over a small JSON record of an accepted twin
(delivery record); Part 2 starts from it
(astra-station new-twin-task --delivery ); the chain orders the stages
(how it runs).

Start

From the checkout root on Linux, create a virtual environment with Python 3.11 or 3.12 and install the three local packages together:

python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install ./real2sim ./policy_development ./end_to_end
source env.sh
real2sim-harness --help
calibrated-scene-reconstruction --help
astra-station --help
astra-e2e schemas

Use python3.12 in the first command if that is your installed version. In a new shell, activate the same virtual environment and source env.sh before running the examples. The offline installation guide describes how to prepare a wheel directory.

The default Vega 1P with Sharpa hands and the standard Franka Panda are included. Optional grasp synthesis uses a separate hand descriptor and solver. See the robot inventory and expected layout.

- An agent working here starts from AGENTS.md.
- Each part documents its own environments. Part 1's reconstruction needs a GPU workstation, Blender 4.5 and Isaac
  Sim 5.1; Part 2's controller is standard library only and its stations run where the site file says.
Scope and limits

- The agent does not operate the real robot. Every record keeps real validation pending until a person has run it.
- A twin is evidence about one capture. Scale comes from legal evidence in the capture, never from the task's true
  dimensions; a simulation score never justifies changing geometry, friction or success definitions.
- Task-specific policy-development code (task specifications, simulator backends of hand-authored tasks, real-robot
  workers) is not part of this release. Supply it as your own task directory in the
  station harness format. This repository holds the
  task-independent parts and the path from a twin to a station.
