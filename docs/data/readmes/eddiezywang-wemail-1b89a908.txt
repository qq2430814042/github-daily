项目简介

工作邮件的真正痛点不是"收不到",而是"读不完、理不清、跟不住":每天上百封系统通知、审批流转和项目讨论混在一个收件箱里,重要信息被淹没,有价值的模式靠人肉规则勉强维持。

WeMail 把邮箱变成一个本地优先的智能工作台:通过 IMAP/SMTP 把邮件同步到本地 SQLite,由本机调度 AI 智能管线 —— 摘要、智能标签、回复草稿、待办提取,以及一个能替你读邮件、起草回复、执行操作的 Agent。AI 请求发送到你配置的模型端点,可能包含邮件元数据、正文和对话内容;使用远程端点时,这些内容会发送给该服务提供方。使用本地模型端点可在本机处理模型请求;遥测默认关闭。

它适合每天被工作邮件淹没、希望在本地获得 AI 辅助又不放心把邮箱交给云端服务的开发者与知识工作者。

核心能力

本地优先邮件引擎

功能:IMAP/SMTP 同步到本地 SQLite,由独立 utilityProcess 工作进程隔离运行。
解决的问题:邮件同步与本地缓存无需 WeMail 自营中间服务器；已缓存内容可离线阅读。
价值:本地保存邮件，断网时仍可查看已缓存内容。同步和发信依赖邮箱服务商，AI 与远程图片请求也可能访问外部服务。

AI 智能管线

功能:根据邮件类型和处理策略生成摘要、主题分类与待办事项；回复决策及条件满足时生成的草稿需要启用对应功能。
解决的问题:读不完的邮件流。
价值:辅助判断邮件内容和后续行动，减少阅读与整理成本。

桌面端默认关闭自动回复决策；设置 WEMAIL_REPLY_DECISION_ENABLED=1 后才会处理该类任务。功能输出还取决于模型配置、邮件类型和处理结果。

用户可控的智能标签

功能:AI 从邮件内容中发现候选主题,经你确认后晋升为正式智能标签,并异步回填历史邮件。
解决的问题:传统规则易碎、纯 AI 自动分类不可信。
价值:AI 提议 + 人确认的混合模式,分类体系完全由你掌控、随时可改。

带护栏的邮件 Agent

功能:基于 Pi 运行时的助手,可读邮件、跨账户检索、起草回复、执行整理动作。
解决的问题:重复性的邮箱操作(归档、打标、催办、汇总)。
价值:硬性安全边界 —— 单次最多 6 轮工具调用、单工具 30s、单次运行 120s;发信及高风险操作需要确认。保存草稿和针对明确指定单封邮件的部分低风险操作可直接执行。

自动化规则与洞察报告

功能:把重复模式固化为可编辑的自动化规则;日报 Digest;基于数据集的洞察报告(独立 HTML 产物)。
解决的问题:AI 每次从头理解的浪费,以及"邮箱发生了什么"缺乏全局视角。
价值:一次沉淀、持续生效;管理层视角的邮箱报表。

企微 / 飞书机器人接入(可选)

功能:把 Agent 接到企业微信 / 飞书群,流式回复(企微打字机、飞书卡片),支持群内审批待办动作。
解决的问题:不在电脑前时也能处理邮件事务。
价值:移动场景闭环,审批动作回到桌面端执行。

效果展示

应用场景

- 每日邮件分诊:早上打开邮箱,AI 已完成摘要与分类,按"待回复 / 待办 / 通知"快速过一遍,重点邮件给出回复草稿。
- 跨项目信息聚合:同主题邮件自动聚成标签,配合日报 Digest 掌握各项目进展,不用翻聊天记录。
- 出差 / 通勤碎片处理:企微 / 飞书机器人里让 Agent 汇总今天的重要邮件、起草回复,回办公室确认发送。
- 制度性邮件批处理:审批流转、系统告警类邮件固化为自动化规则,自动归档 + 提取关键信息。

安装部署

环境要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| Node.js | 22.19+（22.x）或 24.x | 构建 & 运行时；CI 使用 22.x |
| npm | ≥ 10 | 包管理(随 Node) |
| Bun | 使用与锁文件兼容的版本 | 安装根目录依赖 |
| 操作系统 | Windows 10/11；macOS 待验证 | Windows 为主要开发平台，安装包仍需人工验收 |

源码构建从 npm registry 拉取 Electron 二进制与原生模块(better-sqlite3 会按 Electron ABI 自动重建);内网环境建议先配置镜像。

方式一:源码构建(标准)

git clone https://github.com/eddiezywang/wemail.git
cd wemail
bun install --frozen-lockfile # 修补 pi-agent exports，并尝试准备 Electron 原生绑定
npm run build:desktop   # 渲染层(Vite)+ 主进程/服务层(tsc)+ 运行时配置
npm run package:desktop # 使用项目打包脚本产出 Windows 未打包应用

如果安装时提示 Electron 原生绑定准备失败，请在启动或打包桌面应用前运行 npm run ensure:desktop-native。

方式二:开发模式运行

npm run dev:desktop   # Vite dev server + Electron 主进程热启动

验证源码

运行 npm run verify:pr 执行公开仓库的类型检查和测试。

快速开始

npm run dev:desktop        # 启动应用
1. 首页添加邮箱账户(IMAP/SMTP 地址 + 凭据)
2. 设置 → 模型:填入你的 LLM 端点与 API Key(OpenAI / Anthropic 兼容)
3. 等待首轮同步,智能管线自动开始工作

使用说明

- 邮箱连接:设置 → 账户,支持多账户;凭据存入操作系统级加密存储(safeStorage)。
- AI 配置:设置 → 模型,BYOK(Bring Your Own Key);未配置时应用可正常收发邮件,智能功能降级。
- 智能标签:邮件详情卡的候选主题 → "晋升为标签" → 确认名称与规则 → 历史邮件自动回填。
- Agent:侧边栏助手面板支持自然语言指令；发送和高风险操作需要确认，保存草稿及部分明确指定的单封邮件低风险操作可直接执行。
- 机器人(可选):设置 → 连接,管理企微 / 飞书机器人连接。独立 LangBot webhook 路由当前未接入桌面 API，不能按回调入口使用。
- MCP:内置 MCP server，可把邮箱能力暴露给可信的本地 MCP 客户端（设置中开启）；持有连接凭据的客户端可执行写操作，无需应用内二次确认。

系统架构

三层结构、单进程树,全部运行在本机:

- 渲染层不直接触达任何外部服务,一切经本地 API;shared/ 承载跨进程类型契约。
- 服务层与主进程一起由 tsc 编译,无独立后端部署。

Agent 的发送邮件和高风险操作走"待办动作 → 确认令牌 → 执行"链路,执行参数与确认时严格一致。保存草稿和针对明确指定单封邮件的部分低风险操作可直接执行。可选 MCP 是独立权限边界：持有连接凭据的客户端可直接提交发送、移动和删除等操作，无需 WeMail 再次确认。

Prompt 管线

智能管线各处理器(摘要 / 标签 / 回复决策 / 草稿 / 待办)各有独立提示词,统一模式:结构化输入(邮件元数据 + 清洗后正文)→ JSON 约束输出 → zod 校验入库。标签体系分层:内置分类(固定)、用户智能标签(编译为分类提示)、AI 候选主题(仅提议,晋升前不影响历史组织)。

LLM 使用方式

- 完全 BYOK:OpenAI 兼容或 Anthropic 兼容端点,Key 存于系统加密存储,调用模型时会发送给所配置的服务用于身份验证。
- 无任何内置模型转售;智能管线与 Agent 共用同一 LLM 配置。

安全设计

- Agent 发信需确认:草稿与 Agent 动作不会自动发送；可信 MCP 客户端可直接提交发信操作。
- 日志保护:AppLogger 对已识别的敏感字段做脱敏；分享诊断信息前仍需检查并移除敏感内容。
- 远程图片:打开邮件可能通过本机代理访问图片服务器，暴露网络地址及 URL 中的标识；已知像素过滤不能阻止所有追踪。
- Agent 高风险操作需确认:Agent 发信及高风险动作走确认令牌链路；MCP 客户端使用独立权限，不会触发该确认。
- 登出保留数据:删除凭据但保留缓存邮件、智能产物与审计日志
- 留存策略:当前不按固定天数自动清理邮件正文和附件缓存；应用日志默认保留 7 天，部分审计与自动化明细为 30 天，清理在应用运行期间执行。
- 遥测默认关闭:环境变量和打包配置均未提供端点时不会发送遥测(见配置说明)

启用遥测时，事件会包含本机操作系统用户名、安装标识、应用及平台版本和经过校验的事件元数据，并发送到配置的端点。

项目亮点

1. 隐私优先的 AI 邮件:智能能力完整,BYOK,模型数据流向由所配置的端点决定 —— 与"云端读你邮箱"的产品形成根本差异。
2. 运行时硬护栏:Agent 限制(轮数/时长/无发送工具/确认链)实现在运行时层,不依赖提示词自觉。
3. 混合智能标签体系:AI 候选 → 人确认 → 规则沉淀 → 历史回填,兼顾自动化与可控性。
4. 单进程树完成全部隔离:mail-core / db-service / bot-core 各自 utilityProcess,崩溃互不传染。
5. 桌面化改造完整:从 Cloudflare Workers 架构完整迁移到本地优先架构,无云端残留依赖。

FAQ

必须配置 LLM 才能用吗?
不必须。未配置时邮件收发、浏览、搜索完全可用,智能功能(摘要/标签/草稿/Agent)降级隐藏。

我的邮件数据存在哪?
本机用户数据目录下的 SQLite,以及正文缓存。详见安全设计的留存策略。

支持 Exchange / Gmail?
支持配置 IMAP/SMTP 的邮箱；具体服务商可能有授权方式或兼容性要求，尚未逐一验证。专属协议（如 EWS）目前不支持。
