blender-ai-copilot-bridge

An MCP bridge for Blender that exposes 27 supervised scene tools to OpenCode and any compatible client—authenticated Streamable HTTP on a local endpoint, with the visual chat studio and agent teams on the inside.

Your coding agent gets a Blender hand: authenticate once, and the scene answers to get_scene_info, add_cube and export_scene like the rest of your toolchain.

Why

Your agents can read repos, write code and run tests—until the task says "now make it in Blender". blender-ai-copilot-bridge gives every MCP client a safe door into your scene: a local, authenticated Streamable HTTP endpoint that exposes the full supervised toolset—inspect, create, edit, capture, script, export—while approvals and undo stay in Blender. The bundled OpenCode launcher wires the connection for you; other compatible clients plug into the same endpoint with your token.

Quick Start

Every command below is self-contained: open PowerShell, copy it, paste it, press Enter.

1. Download mcp-for-blender-pro.zip from [Releases.
2. In Blender, open Edit → Preferences → Get Extensions → menu → Install from Disk.
3. Select the ZIP, enable mcp-for-blender-pro, then open 3D Viewport → N → MCP Pro.
4. Choose a provider, add your connection details and select a model.
5. Send a message in Blender or click Open Studio Window.

Features

- Expose 27 supervised scene tools to any compatible MCP client.
- Authenticate every request—a generated Bearer token, kept in the client's secret store or environment.
- Launch OpenCode preconfigured—the bundled Portable launcher sets the Blender connection up for you.
- Inspect scenes for your agents—object lists, structure and details returned as structured context.
- Capture the viewport—screenshots that image-capable agents can actually see.
- Keep control in Blender—approvals, cancellation and named undo apply to external calls too.
- Export results—export_scene hands the finished scene to your pipeline.

How it works

blender-ai-copilot-bridge runs inside Blender as an extension: the MCP server publishes the supervised toolset on a local Streamable HTTP endpoint (http://127.0.0.1:9876/mcp) that authorized clients call with a Bearer token, and every call lands as a visible, undoable operation in Blender. Inside, the same toolset powers the visual Studio chat and optional manager–worker–reviewer agent chains; OpenCode Portable gets its connection configured automatically at launch.

Usage

OpenCode in one click. Launch OpenCode Portable from the sidebar, sign in to your providers, pick a model—and ask it to build in Blender; the bridge connection is already wired.

A build brief from your coding agent. Point any MCP client at the endpoint with your token, then let it run get_scene_info, create the layout, set materials and finish with export_scene.

Context, not screenshots. Feed real scene structure to your agents through the inspection tools instead of pasting viewport grabs into chat.

Troubleshooting / FAQ

What is the endpoint address? http://127.0.0.1:9876/mcp by default—enable the MCP server in the extension preferences first and keep Blender open.

How does authentication work? Every request carries an Authorization: Bearer header with your access token; treat it like a password.

Can clients other than OpenCode connect? Yes—any client that supports authenticated Streamable HTTP MCP; configure the endpoint and token in that client.

Is my scene exposed to the network? The endpoint is local; the token gates every call, and operations remain visible and undoable in Blender.

Do approvals apply to external calls? External clients manage their own approval policies—Blender-side undo and operation visibility still apply.
