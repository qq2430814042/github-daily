Saltline：单文件 3D 射击游戏（中文版本）

约 1.4 MB，一个 HTML 文件，一款无需联网的单机 3D 射击游戏。

雨幕中的港区、堆叠的集装箱、湿地上的倒影、枪口的闪光与迎面而来的机械敌人，都装进了这个小小的文件里。无需安装游戏客户端，也无需额外下载模型、贴图或音效资源，使用支持 WebGL 的现代浏览器即可游玩。

游戏介绍

港区防御系统失控，你将以第一人称视角进入封锁区域，穿过集装箱堆场、仓库与码头，切断三处上行中继，突破机械敌人的拦截，最终登船撤离。

这是一段围绕“突入—切断中继—应对增援—撤离”展开的单人行动。你需要观察目标方位，利用场景中的遮挡接近任务点，在移动、瞄准、射击和换弹之间掌握节奏。切断中继会引来新的敌情，完成全部目标后仍需抵达撤离点。

- 完整的任务流程：三处中继、敌人波次、撤离目标与行动结算。
- 第一人称射击反馈：开镜瞄准、后坐力、换弹动作、命中提示和受伤方向提示。
- 雨中的港区氛围：金属锈迹、地面积水、雨滴、软阴影与实时反射。
- 丰富的声音层次：枪声、弹壳、不同地面上的脚步、风雨海浪，以及随战斗强度变化的音乐。
- 键鼠与触屏操作：电脑使用键鼠，触屏设备使用虚拟摇杆和屏幕按钮；可在设置中调整画质。

为什么只有约 1.4 MB？

关键在于：大量素材没有保存成图片、模型和音频文件，而是保存成了“生成这些素材的代码”。

游戏将 Three.js 渲染引擎、玩法逻辑、界面，以及材质、模型、粒子和声音的生成程序一起打包进 HTML。运行时再由浏览器和显卡生成画面，由 Web Audio 播放程序合成的声音，无需额外联网下载素材。

例如，一块生锈铁板不必保存为高清照片：程序先生成金属底色，再叠加不规则锈斑、边缘掉漆、细小划痕和雨水痕迹，最后设置不同区域的凹凸与反光程度。少量规则可以重复组合成丰富的表面细节。

这里的“生成”指数学算法和图形程序生成，并非运行时调用联网 AI 服务。

图片、模型和声音到底从哪里来？

| 你看到或听到的内容 | 这个游戏的实现方式 |
| --- | --- |
| 集装箱、仓库、码头、枪械、机械敌人 | 用代码构造几何体、顶点和零件，再组合成模型 |
| 金属、油漆、锈迹、刮痕、混凝土 | 使用数学噪声与着色器生成纹理 |
| 标识、文字、地面标线、枪身标签 | 使用 Canvas 绘制，再用于场景 |
| 天空、地面湿润感、水洼、海面 | 着色器计算颜色、波动、粗糙度和反射 |
| 烟雾、火焰、火花、弹道、雨水 | 程序生成粒子纹理，再控制粒子的运动与消散 |
| 枪声、脚步、换弹、雷声、海浪 | 数学合成音频数据，由 Web Audio 播放 |
| 背景音乐 | 程序生成多个音乐声部，并根据战斗强度混合 |

为什么大型游戏却要几十 GB？

两者保存的内容量和素材方式不同。大型游戏往往包含大量独立场景、高精度角色、高清贴图、动作、录音和视频；这份游戏把内容集中在港区场景、有限敌人和一套任务流程上，又充分复用了生成规则。

它还直接使用设备上已有的浏览器、图形接口和音频系统，不需要把这些运行环境装进 HTML。

可以把这个文件理解成一本很精细的“制作配方”：文件里保存配方，运行时由 CPU 和 GPU 把场景、纹理、声音做出来。 因此，文件只有约 1.4 MB，但运行时占用的内存、显存和计算资源会大得多。
